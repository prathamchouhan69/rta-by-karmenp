# KARM OS = RTA by KARM — BACKEND AND FEATURES RULEBOOK

This is the single source of truth for all compliance audits. Every check in the audit maps to a rule here.

---

## 0. GENERAL PRINCIPLES

1. **Read-only audit**: The auditor must not change any app code, config, or tests. Only create reports under `reports/audit/`.
2. **Truth**: PASS only if the check was actually run and the raw output saved. Never invent results.
3. **Safety**: Use MOCK Zoho only (`ZOHO_MODE=mock`). Never call real Zoho. Never attack anything except localhost.
4. **Secrets**: No keys, tokens, passwords, GSTIN, bank numbers in any report or log.
5. **Money Law (KARM Law)**: Every ₹ is a Zoho string. The app never computes money figures — only displays Zoho's verbatim strings.
6. **Scope**: Frontend visual design (colors, fonts, 3D, charts, mascot, atlas) is OUT OF SCOPE. Judge only backend, features, money correctness, security, PWA behavior.

## 2. THE LAW OF MONEY (KARM LAW — MOST IMPORTANT)

| ID | Rule |
|----|------|
| M1 | Proxy parses Zoho responses with a **lossless JSON parser**. Show file and line. |
| M2 | Money fields arrive as **exact TEXT** with trailing zeros intact (e.g., "100.50", "2.000"). |
| M3 | Golden invoice `INV-KE-270031`: raw total `"64944.84"` and formatted `"₹64,944.84"` arrive unchanged through proxy. |
| M4 | **Zero money maths in apps/web and packages/shared**: No `+ - * / %` on money-like names, no `parseFloat`, `parseInt`, `Number()`, `toFixed`, `Math.round`, `Intl.NumberFormat`, `toLocaleString`, no `reduce` that adds money. Only `packages/shared/src/groupDigits.ts` may do digit grouping — and only by string slicing. |
| M5 | The **only code creating the `ZohoMoney` type value** is the proxy response mapper. |
| M6 | A POST containing `total`, `sub_total`, `tax_total`, `balance`, `round_off`, or any tax amount is **rejected with 422**. |
| M7 | While editing a document, **no total is shown** and the exact sentence **"Total will be calculated by Zoho Books"** is visible. |
| M8 | The app **never chooses document numbers** — they come from Zoho Books only. |
| M9 | The mock folder is **NOT imported** by `apps/web` or `apps/proxy`. |
| M10 | Where Zoho has no endpoint (balance sheet, P&L, trial balance, audit trail), the app shows a **"Lives in Zoho Books" tile** with an **"Open in Zoho Books" link** — not its own sums. |

## 3. PROXY AND MOCK

| ID | Rule |
|----|------|
| P1 | Every route in this rulebook exists: `/health`, `/organization`, `/contacts`, `/contacts/:id`, `/items`, `/taxes`, the 13 document kinds (GET/POST/PUT), status actions, `/pdf`, `/search`, `/news`, `/auth`, `/audit`, `/agent`. Make a table: route, exists?, tested? |
| P2 | Contract test: call every route against the mock; record status codes. |
| P3 | **Idempotency**: same POST twice with same `Idempotency-Key` → exactly ONE document. Same key 50× at once → ONE. 50 different keys → 50 documents. |
| P4 | POST without `Idempotency-Key` → rejected. |
| P5 | 401 from Zoho: **refresh once and retry once**, never loop (use mock failure switch). |
| P6 | 429: backoff and friendly error. 500 and 8-second slow reply: friendly error, no crash, no duplicate. |
| P7 | Timeout is 15s; retries **only for GET and keyed POST**. |
| P8 | Logs contain **no request/response bodies and no tokens**. Read a real log sample. |
| P9 | Audit log records every write: time **Asia/Kolkata**, device id, route, key, document id. |
| P10 | Login: passphrase hashed with **scrypt or argon2id**; session cookie **HttpOnly, Secure, SameSite=Strict**; lockout after 5 wrong tries; CSRF token required on non-GET. |
| P11 | Passkeys (WebAuthn) present, or record "not built". |
| P12 | Headers on every response: `CSP`, `HSTS`, `X-Content-Type-Options`, `Referrer-Policy`, `Permissions-Policy`; API has `Cache-Control: no-store`. CORS allows only the app origin. |
| P13 | Body limit 1 MB; unknown fields rejected; error messages show no stack traces. |
| P14 | Default `ZOHO_MODE=mock` and a **PRACTICE MODE banner** shows in mock mode. |
| P15 | Mock seed data: ~25 customers incl. "Dilip Buildcon Ltd", 12 vendors, 40 items, 120 invoices; tax cases (CGST+SGST, IGST, exempt, 0/5/12/18/28%). |
| P16 | `SETUP_ME.md` (6 steps), `LIVE_CHECKLIST.md` (20 items), `ENDPOINT_MAP.md`, `AGGREGATES_AVAILABLE.md`, `DOCUMENT_MATRIX.md`, `CYCLE_LEDGER.md` exist and are not empty. |

## 6. SECURITY (localhost only)

| ID | Rule |
|----|------|
| S1 | `npm audit --omit=dev`: list high and critical findings. |
| S2 | Secret scan of repo, dist/, source maps, logs, screenshots (file and line only). |
| S3 | No session cookie → every protected route gives 401. |
| S4 | Forged cross-site POST without CSRF token is blocked. |
| S5 | CORS refuses another origin; no wildcard with credentials. |
| S6 | Injection strings (SQL, NoSQL, command, path traversal) in fields and query params → rejected with 422. |
| S7 | Extra fields (`total`, `balance`, `is_admin`) → rejected with 422. |
| S8 | Oversize body, wrong content-type, deeply nested JSON → rejected safely. |
| S9 | XSS strings (`<script>`, `<img onerror>`, `javascript:`) in customer name, notes, T&C, search, news title → show as plain text; no script runs. |
| S10 | SSRF: URL-taking routes only use an allow-list; `127.0.0.1`, `169.254.169.254`, `file://` blocked. |
| S11 | Changing document ids reaches only the owner's organisation. |
| S12 | Old idempotency key replay creates nothing new. |
| S13 | Changing `X-Forwarded-For` does not escape the rate limit. |
| S14 | Zoho tokens never appear in responses, logs, IndexedDB, localStorage, or service worker caches. |
| S15 | App cannot be put in an iframe. |
| S16 | Lock-screen bypass attempts (routes, back button) show no data. |
| S17 | Sign-out-everywhere kills old cookies. |
| S18 | Brute-force login locks out after 5 tries. |

Record each as **BLOCKED** (attack stopped = PASS) or **NOT BLOCKED** (= FAIL, with severity Critical/High/Medium/Low).
